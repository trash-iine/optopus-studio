# 画面の説明

> この文書は[英語版](../../guide/interface.md)の翻訳です。食い違う場合は英語版が正です。

```
┌──────────────────────────────────────────────────────────────────────────────────────┐
│ optopus studio  [project ▾] ●            Import  Export  New project  [System ▾]     │  ヘッダー
├───────────────────────────┬──────────────────────────────────────────────────────────┤
│                           │ Result  Model  Runs  Compare     Revision [3 (latest)▾]  │
│  you: ...                 │                                               Package    │
│  agent: ...               │ ┌──────────────────────────────────────────────────────┐ │
│  ▸ write_file model.py    │ │ ビュー: 地図、ガントチャート、表、主要な数値 ...     │ │
│  ▸ run_solver             │ └──────────────────────────────────────────────────────┘ │
│                           │ ┌ Convergence ─────────────────────────────────────────┐ │
│                           │ └──────────────────────────────────────────────────────┘ │
│ [+] [message box] [Send]  │ ┌ Heuristic ───────────────────────────────────────────┐ │
│        チャット           │                    キャンバス                            │
└───────────────────────────┴──────────────────────────────────────────────────────────┘
```

画面上のラベルは英語のままです。このページでは英語のラベルで呼びます。

## ヘッダー

| 部品 | 働き |
|---|---|
| プロジェクトのメニュー | プロジェクトを切り替える。プロジェクト名は最初のメッセージから付く。zip から取り込んだものには "(imported)" が付く。開いているプロジェクトの id はページのアドレス(`?project=<id>`)にも入るので、ブックマークすればまた開ける。 |
| ● 点 | ページがサーバーにつながっている間は緑、つながっていない間は灰色。サーバーを再起動したときなどは、ページが 1 秒ごとに自動で再接続する。 |
| **Import** | 他の人がエクスポートしたプロジェクト(`.zip`)を新しいプロジェクトとして開く。 |
| **Export** | 開いているプロジェクトを 1 つの `.zip` でダウンロードする。チャット、結果付きの全リビジョン、添付ファイルを含む。 |
| **New project** | 空のプロジェクトを始める。1 つの課題に 1 つのプロジェクトを使い、変更はその中で頼む。 |
| テーマのメニュー | System、Light、Dark。 |

## チャット(左)

- **メッセージ欄**: **Enter** で送信、**Shift+Enter** で改行。日本語などの IME で変換中の Enter は
  変換の確定になり、送信されない。
- **+**: ファイルを添付する。CSV、TSV、`.txt`、`.xlsx`、JSON(1 つ 20 MiB まで)、またはパッケージ化
  したアプリからエクスポートされたケースの `.zip`。添付したファイルは送信するまで欄の上にチップとして
  表示され、× で外せる。
- **Send / Stop**: エージェントの作業中はボタンが **Stop** になり、押すと中断する。作業が終わるか
  止まるまで、次のメッセージは送れない。
- **▸ の行**: エージェントが使った各ツールと、その対象のファイルやページ。`working…` は考え中。
- メッセージの下の**赤い文字**: エージェントやサーバーからのエラー("the agent stopped: …" など)。
  [トラブルシューティング](troubleshooting.md)を参照。
- **Agent**: このプロジェクトのチャットが使うエージェント(Claude か Codex)。エージェントが作業して
  いないときに切り替えられます。切り替えた先のエージェントは、次のメッセージでそれまでの会話を読み、
  プロジェクトのファイルから続けます。このマシンで動かせないエージェントには "(unavailable)" と付き、
  マウスを重ねると理由が出ます。

会話はプロジェクトに保存されます。後でプロジェクトに戻ると同じエージェントのセッションが再開されるので、
それまでの話を覚えています。

## キャンバス(右)

### Revision と Package

求解のたびに 1 から番号の付いたリビジョンができます。**Revision** メニューで以前のどれでも、その
ファイル・結果・ビューごと表示できます。最新のものには "(latest)" が付きます。古いリビジョンを選んでも
表示が変わるだけで、エージェントは常に最新のファイルから作業を続けます。以前のモデルに戻したいときは、
どの変更を取り消すかをエージェントに伝えてください。

**Package** は選んでいるリビジョンを、エージェント無しで動くアプリとしてダウンロードします。その
リビジョンに `app.json` が必要なので、先にエージェントに「アプリにして」と頼みます。
[README](../../../README.md#packaging-a-model-as-an-app)(英語)を参照してください。

### Result

選んでいるリビジョンの結果を、上から順に表示します。

- **状態の行**(求解中): "Solving revision N with the python worker: 2 / 3 runs, best so far …"。
- **バナー**:
  - 赤 "The solve failed at …": モデルがエラーになった。詳細は *traceback* を開く。エージェントにも
    同じエラーが見えていて、たいていは自分で直す。
  - 黄 "view.py failed": 求解はできたが、その描画に失敗した。
  - 青 "This problem is written in Python…" と **Port to Rust**:
    [最初のセッション](first-session.md#8-python-のモデルが遅いとき)を参照。
- **ビュー**: エージェントがこの問題のために選んだ表示。種類は、主要な数値、表、ガントチャート、
  ルートの地図、グラフ、棒グラフ、文章のメモ、そしてどれも合わないときにサンドボックス内で表示する
  独自の HTML ページ。
- **Convergence**: 各ランでのその時点までの最良目的関数値を、時間または反復回数(グラフ上の
  切り替え)に対して描いたもの。タイトルには optopus の問題とワーカー(python または rust)が出る。
  `BranchAndBound` で解いたときは、最良のランが証明したことも出る。最適性を証明できれば
  "proven optimal"、できなければ到達した限界値(bound)とそこまでの差(gap)。
- **Heuristic**: 探索手法とそのパラメータ、停止条件、シード、ラン数。ランダムな解から始めなかった
  ときは、ランが始まった `instance.json` のキーも出る。

### Model

選んでいるリビジョンのファイル: `model.py`、`view.py`、`instance.json`、`solve.json`、あれば
`app.json` と `rust/main.rs`。ここでは読むだけで、変更はエージェントに頼みます。各ファイルの説明は
[プロジェクト・リビジョン・ファイル](projects.md)にあります。

### Runs

ヒューリスティックのカードに続き、ラン 1 回につき 1 行の表があります。最良値と初期値、反復回数、
最良値が見つかった反復と時間、合計時間、シード。`BranchAndBound` で解いたときは bound の列が
加わります。最良解の最適性を証明したランは "optimal"、それ以外のランは、まだ除外していない解が
達しうる最良の目的関数値です。最良のランは強調表示されます。複数の
ヒューリスティックを比べた求解では、それぞれの最良・平均・最悪の結果と平均時間の表が加わります。

### Compare

2 つのリビジョンを並べて表示します。リビジョンが 2 つ以上必要です。上部のメニューで選びます(最初は
選んでいるリビジョンとその 1 つ前)。

- **Best objective**: 両者の間の変化。良くなったか、悪くなったか、同じかが付く。
  `BranchAndBound` のリビジョンでは、値の横に証明したことが出る。
- **Headline numbers**: 両リビジョンのビューにある数値を行ごとに並べたもの。
- **Convergence of the best runs**: リビジョンごとに 1 本の曲線。
- **Changed files**: 違いのある各ファイルの行単位の差分。"The files are the same; only the runs
  differ" は同じモデルをもう一度解いたことを意味する。
